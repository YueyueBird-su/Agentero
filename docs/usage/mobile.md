# 移动端

Agentero iOS 移动端是桌面 Agentero 的远程客户端，不在手机上创建 Vault，也不在手机上运行 ACP Agent。论文文件、笔记、Catalog 和 Agent 进程都保留在已配对的桌面电脑上。

## 连接电脑

### 桌面端准备

1. 在桌面端打开目标 Vault。
2. 进入 **设置 → 远程访问**，开启 Bridge。
3. 在桌面端显示配对二维码，保持该窗口打开。

### 手机配对

1. 打开 Agentero iOS。
2. 点击 **扫码连接**，扫描桌面端二维码。
3. 检查手机和桌面端显示的确认码。
4. 在桌面端允许本次设备配对。
5. 配对成功后，手机会进入论文库。

无法使用相机时，可以选择 **粘贴配对链接**，粘贴以 `agentero://pair#offer=` 开头的链接。配对凭据保存在 iOS Keychain；之后启动 App 会尝试自动恢复连接。

## 论文库与阅读

移动端主导航包含：

- **论文库**：查看当前桌面 Vault 的论文列表，并搜索标题、作者或标识符。
- **Agent**：连接桌面端 ACP Agent，进行远程对话。

在论文库中点击论文后可以：

- 在 PDF 和笔记之间切换；
- 阅读桌面 Vault 中的 PDF；
- 编辑并保存论文目录下的 `NOTES.md`；
- 从阅读页返回论文库：点击左上角返回按钮，或从屏幕左缘向右轻扫（iOS 侧滑返回）。PDF 内的划词与双指缩放不会触发返回。

PDF 通过 Bridge 分块传输并缓存到手机。缓存不是事实来源；手机离线时只能查看已经缓存的内容，不能保存笔记或运行 Agent。

## 使用 Agent

打开 **Agent** 后，顶部下拉菜单可以切换桌面端已配置且探测成功的 ACP Agent。移动端不会运行 CLI，消息会发送到已配对的桌面端执行。

支持的操作包括：

- 流式查看 Agent 回复；
- 切换不同 ACP Agent；
- 查看并恢复 Agent 历史会话（取决于 Agent 是否支持 ACP 会话列表/恢复）；
- 在 Agent 请求权限时选择允许或拒绝。

切换 Agent 后，当前移动端草稿会重新开始；桌面端已存在的 Agent 进程仍按桌面端权限模式运行。

如果下拉菜单只有默认 Agent：

1. 在桌面端 **设置 → Agent** 执行重新扫描和探测；
2. 确认其他 Agent 显示为 ACP ready，并已完成注册；
3. 重启桌面端 Host 后，在手机上重新进入 Agent 页面。

## 连接状态与断开

打开左上角菜单可以查看当前电脑、Vault 和在线状态，也可以断开连接或重新配对另一台电脑。

桌面端退出、Bridge 关闭或网络中断时，移动端会显示离线状态。恢复前台或网络恢复后，App 会尝试重新连接并刷新论文列表；未完成的写操作不会在手机端排队等待回写。

## 数据与安全边界

- Vault 文件和 `.agentero/catalog.sqlite` 始终以桌面端为准。
- 手机只保存设备密钥、配对信息和可丢弃的 PDF/内容缓存。
- Bridge 使用 Relay 转发加密数据，Relay 不负责解密 Vault 或 Agent 内容。
- 新设备首次连接必须在桌面端人工确认；已配对设备可在桌面端远程访问设置中吊销。


## 自定义与局域网中继

桌面设置 → 远程访问中的「中继地址」接受 `wss://host:port`、`ws://LAN-IP:port` 或默认按 WSS 解释的 `host:port`。关闭远程访问后才能修改地址；成功启动后保存在本机 Web Storage，空值使用官方默认地址。

局域网 WS 测试时，桌面和手机必须能访问同一中继地址。二维码对 WS 保留显式协议，避免手机误按 WSS 发起 TLS；现有 WSS 二维码格式保持兼容。变更中继或桌面身份后，应重新扫描桌面生成的配对二维码。

中继仍需兼容客户端使用的公钥编码。0.13.0 手机端的 `e2ee_hello.key` 是无填充 Base64URL；严格只接受标准 Base64 的中继应先实现显式兼容配置。WS 测试仍保留应用端到端加密、配对批准与签名认证，不应通过放行任意公钥或跳过设备验证解决兼容问题。

独立本机测试构建可使用 `pnpm tauri build --debug --bundles app --config src-tauri/tauri.lan.conf.json`。该覆盖配置使用单独的 App 标识，辅助资源需先按正常开发流程 stage；本机测试还复用了同版本已安装官方 App 的未修改 PDFium、插件 worker 和 adapters。它不是完整发行版打包替代流程。

LAN 覆盖构建通过 `VITE_AGENTERO_RELAY_ENDPOINT` 设置默认中继为 `ws://10.112.112.91:4000`，要求该固定穿透地址属于运行中继的 Mac，且手机已接入相同组网。普通构建未设置该变量时仍使用官方地址。已有手动保存的中继配置优先，不会被构建默认值覆盖。

个人 fork 的 `LAN desktop packages` 工作流构建 macOS arm64/x64、Linux x64/arm64、Windows x64。开发分支推送相关文件会上传 Actions artifacts（保留 14 天）；推送指向此分支提交的 `lan-v*` 标签（例如 `lan-v0.13.0-20261027.1`）后，全部平台成功才自动创建测试版 Release 并附安装包和 SHA256SUMS。手动触发入口需工作流已存在默认分支；无需改变默认分支即可用上述分支推送/标签触发。该独立流程不要求上游 updater、Apple 或 Android 签名密钥，不生成 CLI 或移动端包；未签名/未公证构建的系统提示仍适用。Windows 构建也会完整准备 PDFium、adapters 和插件 worker，不能复用 Mac 二进制。
